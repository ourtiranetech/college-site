## When to Use

Use this reference when:
- `Convex functions should not be imported in the browser` error occurs
- `useQuery`/`useMutation` receives a plain string (e.g. `"messages:getMessages"`) instead of a `FunctionReference`
- `tsc` reports `Argument of type 'string' is not assignable to parameter of type 'FunctionReference<"query">'`
- Adding a new Convex query/mutation to a React page
- Implementing paginated queries with `usePaginatedQuery`

## The Core Rule

### ✅ CORRECT: Use the generated `api` object

```typescript
import { api } from '../../convex/_generated/api'
import { useQuery, useMutation } from 'convex/react'

// Query
const messagesQuery = useQuery(api.messages.getMessages, { salle })
const envoyer = useMutation(api.messages.envoyerMessage)

// Mutation
await envoyer({ salle, contenu: message })
```

### ❌ WRONG: Import Convex functions directly

```typescript
import { getMessages, envoyerMessage } from '../../convex/messages'
// or
useQuery("messages:getMessages", { salle })
```

This throws:
```
installHook.js:1 Convex functions should not be imported in the browser.
```

**Why:** The generated `_generated/api.js` wraps each exported function in a `FunctionReference` that the Convex client validates (using `makeFunctionReference`). Direct imports bypass this validation and try to run the function in the browser, where `ctx.db` and other server-only APIs do not exist.

## Generated API Access

The file `convex/_generated/api.d.ts` (and `api.js`) is regenerated by `npx convex dev`. It exports:

```typescript
export const api: FilterApi<typeof fullApi, FunctionReference<any, "public">>
export const internal: FilterApi<typeof fullApi, FunctionReference<any, "internal">>
```

Access patterns:
```typescript
api.messages.getMessages     // query FunctionReference
api.messages.envoyerMessage  // mutation FunctionReference
api.messages.getUploadUrl    // mutation FunctionReference
```

Do not re-type or re-declare these references manually — always import from `_generated/api`.

## Pagination with usePaginatedQuery

### Server query definition

```typescript
// convex/messages.ts
import { query } from "./_generated/server"

export const getMessages = query({
  args: {
    salle: v.string(),
    paginationOpts: v.object({
      numItems: v.number(),
      cursor: v.string(),
      id: v.number(),
    }),
  },
  handler: async (ctx, args) => {
    const { salle, paginationOpts } = args
    const { numItems, cursor } = paginationOpts
    return await ctx.db
      .query("messages")
      .withIndex("by_salle", (q) => q.eq("salle", salle))
      .order("desc")
      .paginate({
        numItems,
        cursor: cursor ?? null,
      })
  },
})
```

**Important:** `paginationOpts` is an **object** (not `v.optional(v.any())`). The client injects `paginationOpts` automatically; the server reads `numItems` and `cursor` from it.

### Client hook

```typescript
import { usePaginatedQuery } from 'convex/react'
import { api } from '../../convex/_generated/api'

function ChatPage() {
  const messagesQuery = usePaginatedQuery(
    api.messages.getMessages,
    { salle },                    // args (paginationOpts is injected by the hook)
    { initialNumItems: 50 }       // first page size
  )

  // results
  const messages = messagesQuery.results ?? []

  // status
  if (messagesQuery.status === 'LoadingFirstPage') return <div>Chargement...</div>
  if (messagesQuery.status === 'Exhausted') return <div>Fin des messages</div>
  if (messagesQuery.status === 'CanLoadMore') {
    // call loadMore() to fetch the next page
  }

  return (
    <div>
      {messages.map(msg => <div key={msg._id}>{msg.contenu}</div>)}
    </div>
  )
}
```

### Pagination status values

| Status | Meaning |
|--------|---------|
| `LoadingFirstPage` | The first page is loading |
| `CanLoadMore` | More pages exist; call `loadMore()` |
| `LoadingMore` | Next page is loading |
| `Exhausted` | All pages loaded |

### Loading more pages

```typescript
if (messagesQuery.status === 'CanLoadMore') {
  messagesQuery.loadMore(50) // fetch next 50 items
}
```

## Common Pitfalls

### 1. `paginationOpts` is required, not optional

```typescript
// WRONG
paginationOpts: v.optional(v.object({ ... }))

// CORRECT
paginationOpts: v.object({ numItems: v.number(), cursor: v.string(), id: v.number() })
```

The `usePaginatedQuery` hook always injects `paginationOpts`, so the server query needs it unconditionally.

### 2. Don't pass `paginationOpts` or `take`/`skip` as client args

The `usePaginatedQuery` hook signature:
```typescript
usePaginatedQuery(query, args, options)
```
- `args`: your query arguments **excluding** `paginationOpts` (the hook injects it)
- `options`: `{ initialNumItems: number }` — the first page size

### 3. Don't use `useQuery` for paginated queries

`useQuery` returns a single page (or null). Use `usePaginatedQuery` for paginated data. The result shape is different:
- `useQuery`: returns the data directly (or `null`)
- `usePaginatedQuery`: returns `{ results, status, isLoading, loadMore }` — always an object

### 4. Verify generated API is fresh

After adding a new query/mutation, run `npx convex dev` to regenerate `convex/_generated/api.d.ts` and `api.js`. If your import fails, check that these files exist and contain the new function.
